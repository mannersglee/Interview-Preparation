# 机器学习与推荐系统

## 机器学习基础

**Q：过拟合、欠拟合？** 过拟合是在训练集好、未见数据差；欠拟合是训练和验证都差。排查顺序是划分与泄漏、基线、特征、模型容量、正则化、样本量和分布漂移。

**Q：训练/验证/测试集如何划？** 验证集用于调参，测试集用于最终估计泛化。用户行为数据常按时间切分，避免把未来行为用于预测过去；同用户重复样本需注意跨集合泄漏。

**Q：L1 与 L2 正则化？** L1 倾向产生稀疏系数，可做特征选择；L2 平滑缩小系数，通常更稳定。系数解释依赖特征标准化和共线性。

**Q：Precision、Recall、F1、AUC？** Precision 关注预测为正中多少真阳性；Recall 关注真阳性找回多少；F1 是二者调和平均；ROC-AUC 衡量随机正例得分高于负例的排序能力。极不平衡数据还应看 PR-AUC、阈值下成本和校准。

**Q：数据泄漏有哪些？** 使用标签发生后的特征、全量数据先做目标编码或标准化、按随机行切分高度相关的用户时序数据、用测试集反复调参。先画预测时点的可用数据边界。

**Q：离线高、线上差？** 可能是训练/服务不一致、采样偏差、曝光偏差、反馈延迟、分布漂移、线上约束、系统延迟或目标不一致。先核对日志与特征，再灰度实验。

## 推荐系统链路

**Q：召回、排序、重排分别做什么？** 召回从海量候选中快速找相关内容，排序细致预测价值，重排处理多样性、频控、公平、商业约束等列表级目标。各层在延迟和精度间权衡。

**Q：协同过滤和内容推荐？** 协同过滤利用用户-物品交互相似性，内容推荐利用文本、图像、标签等特征。新物品缺交互时内容特征有帮助；新用户可用上下文、热门或有限探索。

**Q：负采样问题？** 未点击不一定是不喜欢，可能根本没曝光；应区分曝光未点击与未曝光。采样策略改变训练分布，评估和校准时要考虑这一点。

**Q：CTR/CVR 预估为什么要校准？** 出价和预算决策需要概率有实际意义；排名好不代表概率准。可按分箱比较预测概率与实际发生率，并看不同人群和时间的稳定性。

**Q：多目标优化？** 点击、时长、留存、收入和体验可能冲突。明确主目标、护栏和约束；不能只优化单一短期指标而牺牲长期用户价值。

**Q：冷启动？** 新用户缺历史行为、新内容缺反馈。可以用内容/上下文特征、热门先验、少量探索与多样性策略；需防止新内容长期没有曝光形成反馈循环。

## 离线指标和线上验证

| 指标 | 说明 | 陷阱 |
| --- | --- | --- |
| Recall@K | 相关物品中被前 K 个结果找回的比例 | 依赖“相关”的标签定义与曝光偏差 |
| Precision@K | 前 K 个中相关的比例 | 不反映相关物品的全量覆盖 |
| NDCG@K | 考虑位置与相关性等级的排序指标 | 不直接代表留存或满意度 |
| AUC | 正负样本整体排序能力 | 不反映特定 top-K 和概率校准 |
| 覆盖率/多样性 | 被推荐物品或类别分布 | 可能与短期点击目标冲突 |

**Q：为什么离线提升不保证线上收益？** 离线标签受旧策略曝光影响；新策略改变用户行为和内容供给。线上需 A/B 验证主指标与护栏，监控冷启动、延迟和长期效果。

## 面试准备最低线

能白板说明热门推荐与 item-based 协同过滤基线；按时间切数据；计算 Recall@K 和 NDCG@K；讲 3 个失败案例；设计一次推荐 A/B。若 PyTorch、Transformer 尚在学习，不应写“熟练”或把练习说成生产系统。
