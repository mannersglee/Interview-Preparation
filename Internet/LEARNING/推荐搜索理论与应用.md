# 推荐与搜索：理论、系统和公开实践

## 本文缩写

BM25（Best Matching 25，经典概率相关性排序函数）；ANN（Approximate Nearest Neighbor，近似最近邻检索）；LR（Logistic Regression，逻辑回归）；GBDT（Gradient Boosting Decision Tree，梯度提升决策树）；FM（Factorization Machine，因子分解机）；DeepFM（Deep Factorization Machine，深度因子分解机）；ROC（Receiver Operating Characteristic，受试者工作特征曲线）；AUC（Area Under the ROC Curve，ROC 曲线下面积）；NDCG（Normalized Discounted Cumulative Gain，归一化折损累计增益）；DCG（Discounted Cumulative Gain，折损累计增益）；CTR（Click-Through Rate，点击率）；CVR（Conversion Rate，转化率）；LLM（Large Language Model，大语言模型）；MTGR（Meituan Generative Recommendation，美团生成式推荐）；MTFM（Meituan Foundation Model for Recommendation，美团推荐基座模型）。`@K` 表示只看前 K 个结果。下文沿用缩写。

## 1. 两类问题，一条共同链路

推荐从用户兴趣出发寻找内容，搜索从用户明确 query 出发寻找结果。两者通常都要在严格延迟预算内完成：**候选生成/召回 → 粗排 → 精排 → 重排 → 展示与反馈日志**。搜索额外强调 query 理解、词项/语义相关性；推荐更强调长期兴趣、探索与供给生态。

## 2. 召回：从海量候选到可排序集合

- **词项召回**：倒排索引、BM25 等适合字面匹配和可解释关键词；对同义、长尾表达可能不足。
- **向量召回**：双塔模型将用户/query 与物品编码，近邻检索扩展语义匹配；训练目标与索引时效要一致。
- **协同召回**：item-to-item 或用户行为相似性，适合有交互数据的内容；冷启动、热门偏置明显。
- **规则/业务召回**：新内容、地理位置、关注关系、运营约束等；需做融合配额和去重。

**理论基础：**双塔常优化正负样本区分；ANN 索引以少量召回损失换取时延。召回阶段看 Recall@K、覆盖率、延迟、索引新鲜度和分群表现，不能只看单一路的点击率。

**简化公式：**双塔可用 `score(u,i)=dot(f_user(u),f_item(i))` 对候选打分，便于预先计算物品向量；但仅用点积难表达复杂的实时用户-物品交互，因此后续排序通常使用更丰富的特征。BM25 的直觉是“词项出现次数增加有收益但逐渐饱和，稀有词更有区分力，同时校正文档长度”；不能只把关键词出现次数相加。

YouTube 经典论文公开了候选生成与排序两阶段架构；它是基础范式，不能当作 2026 年所有大厂架构的完整描述。[Google Research：YouTube 推荐](https://research.google.com/pubs/pub45530.html)

## 3. 排序：预测用户与业务价值

特征通常来自用户、内容/商品、query、上下文和交叉项。基础模型可从 LR、GBDT、FM/DeepFM、双塔和序列模型逐步学习。多目标可能同时预测点击、观看、下单、复访、投诉；排序分数需结合业务目标、概率校准及约束。**训练样本按时间切分**，特征必须在预测时刻可得。

排序误差常来自：旧策略曝光偏差、未点击不等于不喜欢、延迟转化、位置偏差、标签定义变化、训练/服务特征不一致。离线 AUC、NDCG 等只能筛选候选方案；最终依靠线上实验评估长期行为与护栏。

**常用损失与指标：**二分类 CTR/CVR 预估常以交叉熵训练；排序任务还可用 pairwise/listwise 目标。`Recall@K = 前K个命中的相关物品数 / 全部相关物品数`；`NDCG@K` 用位置折损加权相关性，再除以理想排序的 DCG。离线指标要按 query、用户、内容新旧等分群看，避免总体均值掩盖长尾。

## 4. 重排与生态

重排处理列表级多样性、重复、频控、新内容探索、商家/创作者公平与广告负载。短期 CTR 最大化可能让头部内容越来越集中，形成反馈循环。快手公开的 KuaiRec 数据研究讨论了曝光选择偏差对离线评估的影响；美团也公开讨论推荐中的选择性偏差和流行度偏差。[KuaiRec 论文](https://arxiv.org/abs/2202.10842)、[美团 Debiasing 实践](https://tech.meituan.com/2020/08/20/KDD-Cup-Debiasing-Practice.html)

## 5. 搜索的特殊问题

**Query 理解**：分词、意图识别、改写、纠错、实体与属性抽取；对电商还要识别品牌、价格、地理与供给约束。相关性至少包括“语义匹配”“可售/可服务”“用户意图满足”。搜索评价可分 query 级、用户级与订单级，避免热门 query 掩盖长尾失败。

**混合检索**：词项与向量召回各有长处，融合时要处理跨路分数不可比、去重、配额与延迟。**无结果率**下降不一定代表体验提升；放松相关性可能增加错误结果。

美团公开的多业务搜索排序实践把系统拆为召回、粗排、多路融合、精排和重排，并指出不同业务对距离、目标和样本量的需求不同。[美团技术团队：多业务搜索排序](https://tech.meituan.com/2021/07/08/Multi-Business-Modeling.html)

## 6. 2025–2026 年公开落地方法

- **更丰富的召回建模**：Meta 公开的 Instagram Explore 双塔用于多目标召回；2026 年 SilverTorch 将索引与模型更紧密融合，在召回阶段应用更丰富的交互和多任务打分。这表明传统“召回只做简单相似度”的假设正在变化，但时延仍是硬约束。[Meta Explore](https://engineering.fb.com/2023/08/09/ml-applications/scaling-instagram-explore-recommendations-system/)、[Meta SilverTorch](https://engineering.fb.com/2026/05/26/ml-applications/silvertorch-index-as-model-new-retrieval-paradigm-recommendation-systems/)
- **序列与跨场景兴趣**：美团公开 MTGR 和 MTFM，用行为序列及跨业务兴趣建模改进外卖推荐，同时强调算力与服务成本控制。[美团 MTGR](https://tech.meituan.com/2025/05/19/Meituan-Generative-Recommendation.html)、[美团 MTFM](https://tech.meituan.com/2026/09/22/Meituan-Foundation-Model-for-Recommendation.html)
- **语义表征结合传统特征**：美团搜索 3.0 公开探索 LLM query 语义表征与交叉统计特征结合，说明语义信息补充而非自动替代行为统计。[美团搜索 3.0](https://tech.meituan.com/2026/08/20/01-meituan-Query-3.0.html)

这些案例来自公开文章，不能推断你所投具体团队正在使用同一方案。

## 7. 自己如何做一个可信小项目

选公开交互数据：先做热门推荐和 BM25/协同过滤基线，再做双塔或序列模型；按时间切分，比较 Recall@20、NDCG@20、覆盖率、冷启动分群和推理时延。报告明确曝光偏差、未观测反馈、特征可用时间和上线实验设计。搜索可用 query-document 标注做词项、向量、融合三路对比。
