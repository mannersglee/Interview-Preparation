# 互联网因果推断理论与应用

## 本文缩写

ATE（Average Treatment Effect，平均处理效应）；ATT（Average Treatment Effect on the Treated，受处理者平均处理效应）；CATE（Conditional Average Treatment Effect，条件平均处理效应）；A/B（A/B Test，A/B 对照实验）；RDD（Regression Discontinuity Design，断点回归设计）；DiD（Difference-in-Differences，双重差分）；DML（Double/Debiased Machine Learning，双重/去偏机器学习）；IV（Instrumental Variables，工具变量）；PSM（Propensity Score Matching，倾向得分匹配）；IPS（Inverse Propensity Scoring，逆倾向得分加权）；DR（Doubly Robust，双重稳健估计）。Uplift 指增量效果建模，不是首字母缩写。下文沿用缩写。

## 1. 从相关到反事实

潜在结果框架定义同一个体在处理和未处理下的结果 `Y(1)`、`Y(0)`，个体效应为 `Y(1)-Y(0)`。现实只观察到一个结果，核心任务是找可信的反事实。**ATE** 是总体平均效应，**ATT** 是受处理者平均效应，**CATE** 是给定特征下的条件效应；不同业务决策需要不同估计对象。

例子：高活跃用户更容易领优惠券，也更容易下单。领券用户下单率高，不能直接证明优惠券有效；需要随机分配或充分论证观察数据的可比性。

## 2. 方法选择树

1. 能随机化且干扰可控？优先 A/B 实验。
2. 有明确阈值决定处理？考虑 RDD，结论多为阈值附近局部效应。
3. 有处理前后及可比对照组？考虑 DiD，检查平行趋势、同期冲击和溢出。
4. 只有观察数据且关键混杂可测？考虑匹配/加权、结果回归或 DML，重点看重叠性、平衡性、未测混杂敏感性。
5. 有可信工具变量？考虑 IV，但排除限制往往最难论证。

| 方法 | 核心估计与假设 | 必做诊断 |
| --- | --- | --- |
| PSM/倾向加权 | 观测协变量条件下无未测混杂；处理概率有重叠 | 干预前特征、倾向分布、平衡、极端权重 |
| DiD | 若无策略，两组趋势平行 | 预趋势、安慰剂、同期政策、处理外溢 |
| RDD | 阈值附近个体可比，不能精确操控阈值 | 密度、协变量连续性、带宽敏感性 |
| DML | 正交化和交叉拟合降低高维模型误差的影响；识别假设仍需成立 | 交叉拟合、重叠性、稳健性 |
| IPS/DR | 已知或正确估计处理概率；DR 结合倾向与结果模型 | 正值性、权重方差、策略概率日志 |

**两个常用估计式：**DiD 的两期估计是 `(处理组后均值-处理组前均值) - (对照组后均值-对照组前均值)`；这是“趋势差”，其因果解释依赖平行趋势。IPS 的核心是按处理概率的倒数对观察结果加权，低概率样本权重极大会导致高方差；实际应用常需检查权重分布与有效样本量。公式本身不验证假设。

**DML 不等于“用机器学习自动消除偏差”**；它改善某些估计步骤，但未测混杂依然可能破坏因果结论。

## 3. 从平均效果到个体化策略

普通转化模型估 `P(Y=1|X)`，Uplift 估 `E[Y(1)-Y(0)|X]`。高转化人群可能无需补贴；预算应分配给预期增量足够大、成本可控的人。个体效应不能直接观察，需随机探索数据、合适的离线评估和线上 A/B 验证。策略优化还要加入预算、频控、公平、长期留存与风险约束。

## 4. 工业实践：公开案例

Meta 公开披露 Instagram 通知场景：对可发通知做随机发送/丢弃，训练 uplift 模型估计通知的增量影响，再在发送率约束下选择通知。这比只预测点击概率更贴近“这条通知是否带来额外价值”。[Meta Engineering：通知个性化与因果推断](https://engineering.fb.com/2022/10/31/ml-applications/instagram-notification-management-machine-learning/)

Netflix 公开介绍了观察性因果分析工具：先想象目标随机实验，再以此约束观察研究的时间零点、处理定义和诊断；Agent 可以帮助执行流程，但关键识别判断仍需要人审。[Netflix 技术博客：Agent 辅助因果推断](https://netflixtechblog.com/a-human-augmenting-agentic-workflow-for-causal-inference-4623f0a9c5af)

## 5. 典型互联网问题

- **补贴或优惠券**：目标应是净增订单/留存而非领券人群原始转化率；处理用户可能影响未处理用户，注意市场干扰。
- **推荐策略**：历史日志只记录旧策略曝光内容，未曝光内容无反馈；离线评估要考虑曝光偏差、正值性和策略概率。
- **内容生态**：激励作者可能改变平台供给，用户级随机实验低估或误估生态总效应；考虑聚类设计与长期观察。
- **地域政策**：DiD 需寻找可信对照地域，并检查预趋势、其它同时发生的活动。

## 6. 实操报告模板

写明：决策问题 → 目标实验 → 处理/对照与时间零点 → 数据和混杂图 → 方法及假设 → 平衡/趋势/重叠诊断 → 效应及区间 → 敏感性 → 可推广范围 → 业务建议。无法验证的假设要直接列出，不用模型复杂度掩盖。
