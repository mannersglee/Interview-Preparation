# 互联网业务分析手册：从异动到可执行建议

## 本文缩写

SQL（Structured Query Language，结构化查询语言）；JOIN（SQL JOIN，表连接操作）；A/B（A/B Test，A/B 对照实验）；DAU（Daily Active Users，日活跃用户数）；CTR（Click-Through Rate，点击率）；GMV（Gross Merchandise Value，商品交易总额）；CVR（Conversion Rate，转化率）；ID（Identifier，标识符）；Agent（AI Agent，人工智能智能体，其中 AI 为 Artificial Intelligence，人工智能）。下文沿用缩写。

## 1. 分析的目标

数据分析不是罗列图表，而是帮助决定“是否上线、继续观察、回滚或补充实验”。标准链路：**业务问题 → 可计算指标 → 数据验真 → 结构拆解 → 假设与验证 → 决策及风险 → 复盘**。

## 2. 异动分析六步

1. **确认异动**：绝对变化、相对变化、基线波动、置信区间、是否跨周内周期。不要看到一天下降就断言趋势。
2. **先验数据**：埋点、版本、时区、重复日志、延迟、数据回填、看板口径及 JOIN 扩行。
3. **拆构成**：新老用户、渠道、设备、地区、版本、时段、品类、query、作者/商家层级；优先找对总变化贡献最大的分组。
4. **拆链路**：如 `订单量 = 访问人数 × 商品点击率 × 点击到下单率 × 人均下单次数`，判断哪一环节变化。
5. **列并验证假设**：每个假设配一条查询、对照或实验；先排系统故障，再看策略与外部因素。
6. **给行动建议**：明确负责人、预期变化、护栏、观察窗口和回滚条件。

## 3. 常用分析方法

| 方法 | 适用问题 | 主要局限 |
| --- | --- | --- |
| 分群/贡献分解 | 哪些人、地区或场景贡献了变化？ | 分组相关不等于分组原因 |
| 漏斗分析 | 哪个环节流失？ | 用户顺序、跨端身份和时间窗常出错 |
| Cohort 分析 | 新用户质量是否变化？ | 需统一观察时间，防止未成熟 cohort 偏低 |
| 归因分析 | 变化与哪些因素相关？ | 营销触点归因常有选择偏差，不等于增量因果 |
| A/B 实验 | 策略是否造成变化？ | 分流污染、网络效应、测量质量会破坏可信度 |
| 准实验 | 无法随机化时估计增量 | 依赖更强、常不可完全检验的识别假设 |

## 4. 三个完整案例

### 案例 A：DAU 降 8%

先查活跃事件是否漏报，按新用户和老用户贡献拆分；若新用户少，查渠道投放与注册漏斗；若老用户回访降，查版本、性能、内容供给和关键行为。对“新版本导致下降”的判断可看灰度组与未升级组，但仍需考虑自主升级选择偏差。输出应是“哪个分组损失多少 DAU、什么证据支持原因、下一步如何验证”。

### 案例 B：搜索 CTR 升、GMV 降

拆 query 意图、位置、类目、价格带和新老用户；确认是点击诱导、低价商品占比变动、CVR 下跌还是订单回填延迟。CTR、CVR、客单价和 GMV 的分母粒度要一致。上线决策要看用户满意度、退款和长期复购护栏。

### 案例 C：Agent 调用量升、任务成功率降

按任务 ID 去重，检查入口曝光、重试次数、用户/任务类型变化；抽样人工复核自动成功判定。若新功能扩大到困难任务，整体成功率下降可能是构成变化；需同时报告固定任务集和真实流量表现。

## 5. 工业实践：分析平台与数据血缘

美团公开描述了推荐系统质量模型，将线上请求异常与数据、特征、模型及发布链路关联，利用血缘信息定位问题；这是“先验链路，再解释业务”的工程化例子。[美团技术团队：推荐系统质量模型](https://tech.meituan.com/2022/06/16/Recommendation-System-Quality-Model.html)

Netflix 公开的实验分析平台把指标、统计模型和可视化模块化，使分析方法可重复使用；这类设计适合避免“同一实验每次都临时写一套脚本”。[Netflix 技术博客](https://netflixtechblog.com/reimagining-experimentation-analysis-at-netflix-71356393af21)

## 6. 交付模板

一页业务 memo 应包含：**问题与口径、数据质量检查、关键拆解图、最可能的 2–3 个机制、验证证据、建议、护栏、局限**。图表标题直接写结论，脚注写样本量、时间窗和数据来源。
