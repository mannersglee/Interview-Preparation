# 互联网行业指标大全：从业务目标到可计算口径

## 本文缩写

CTR（Click-Through Rate，点击率）；SRM（Sample Ratio Mismatch，样本比例不匹配）；GMV（Gross Merchandise Value，商品交易总额）；DAU/WAU/MAU（Daily/Weekly/Monthly Active Users，日/周/月活跃用户数）；D7（Day 7，第 7 天）；LTV（Lifetime Value，用户生命周期价值）；CAC（Customer Acquisition Cost，获客成本）；UGC（User-Generated Content，用户生成内容）；ROI（Return on Investment，投资回报率）；AI（Artificial Intelligence，人工智能）；CVR（Conversion Rate，转化率）；SQL（Structured Query Language，结构化查询语言）；Agent（AI Agent，人工智能智能体）。下文沿用缩写。

## 1. 指标为什么先于模型

任何策略都要先回答“希望谁在多长时间内发生什么变化”。同一名称在不同业务可能口径不同：CTR 可按曝光次数、曝光用户、搜索会话计算；留存可以指第 7 天活跃，也可以指前 7 天内任一天活跃。指标字典至少记录：**业务问题、分子、分母、去重键、时间窗、时区、过滤条件、延迟回填、数据表、负责人和版本**。

## 2. 指标分层

| 层级 | 作用 | 例子 | 常见错误 |
| --- | --- | --- | --- |
| 北极星/长期价值 | 表示持续创造的用户或商业价值 | 有效留存、长期消费、质量合格的任务完成 | 只看单日点击 |
| 主指标 | 本次实验主要判断依据 | 7 日留存、搜索成功率、下单用户数 | 事后挑显著指标 |
| 过程指标 | 解释机制与定位漏斗 | 曝光、点击、观看、加购 | 把过程改善直接当最终收益 |
| 护栏 | 防止副作用 | 投诉、退款、时延、创作者流失、成本 | 主指标提升但护栏恶化仍上线 |
| 质量指标 | 保证测量可信 | 日志覆盖、延迟、重复率、SRM | 先解释业务，后发现埋点坏了 |

**指标树例子：**`GMV = 有购买意图的搜索用户数 × 搜索到下单转化率 × 人均订单数 × 客单价`。这只是分析分解，实际业务需处理多渠道归因、退款与跨日订单。指标树用于定位，不能单凭分解证明因果。

## 3. 通用用户与增长指标

- **DAU/WAU/MAU**：指定活跃事件下日/周/月去重用户数。必须明确游客、跨设备、机器人、时区和自然日/滚动窗。
- **新增**：首次满足注册或激活条件的用户；注册、首开、首次有效使用不是同一个事件。
- **留存**：cohort 中在指定后续窗口仍活跃的人数 / cohort 人数。次日留存、D7 留存和滚动 7 日留存不可混用。
- **流失/召回**：先设定沉默阈值，再定义重新活跃；阈值应结合产品使用周期。
- **LTV/CAC**：生命周期价值与获客成本；早期样本需要预测和不确定性，避免用短期收入替代长期价值。

## 4. 内容、搜索、电商、广告与直播

| 场景 | 链路与核心指标 | 重要护栏 |
| --- | --- | --- |
| UGC/推荐 | 有效作者→内容供给→可分发内容→曝光→有效观看→互动→用户/作者留存 | 低质内容、举报、头部集中、创作者公平 |
| 搜索 | query→有结果→相关曝光→点击→任务完成/下单→复访 | 无结果率、首结果相关性、用户满意度 |
| 电商 | 访问→商品曝光→点击→加购→支付→履约→复购 | 退款、售后、履约成本、商家生态 |
| 广告 | 可投候选→竞价/匹配→展示→点击→转化→增量收益 | 广告负载、用户体验、预算与 ROI |
| 直播 | 主播开播/供给→推荐曝光→进房→观看→互动/付费→双边留存 | 主播收益分布、内容安全、投诉 |
| Agent/AI 搜索 | 任务发起→检索/工具调用→答案/动作→用户确认→复访 | 幻觉、人工接管、时延、成本、安全 |

**CTR = 点击 / 曝光**，**CVR = 转化 / 指定前置行为**；必须说明次数级还是用户级。**任务成功率**应按任务而不是消息数计算，且要有可复核的成功判定。对推荐或搜索，单一 CTR 会放大“吸引点击但不满足需求”的内容。

## 5. 画像和标签质量

标签质量不能只看覆盖率。至少看覆盖率、抽样核验准确性、时效、稳定性、分群误差、误判成本与策略应用后的增量价值。特征观察窗必须早于结果预测窗，避免时间泄漏。标签变化若来自埋点或口径更新，要与真实用户变化区分。

## 6. 实际落地：指标字典与可复现计算

Netflix 公开介绍过将指标定义集中管理，使用可生成 SQL 的 Metrics Repo 与可复用因果分析模块，减少不同分析师对同一指标各写一套口径的风险；这说明指标治理与统计方法同样重要。[Netflix 技术博客](https://netflixtechblog.com/reimagining-experimentation-analysis-at-netflix-71356393af21)
