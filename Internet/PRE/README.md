## 现有优势与待补缺口

根据本仓库此前简历材料：已有统计学、动态因果效应研究、Python 数据处理与量化策略评估经历；SQL 熟练程度、互联网 A/B 实验实操、推荐系统项目、PyTorch 使用经历尚无可核实证据。准备时可把前者讲透，把后者做成练习并明确称为**模拟项目**，不把模拟结果说成实习业绩。

| 优先级 | 缺口 | 达标证据 |
| --- | --- | --- |
| P0 | SQL 与指标口径 | 45 分钟完成留存、漏斗、分组聚合、窗口函数 4 道题；写清分母、去重、时间窗 |
| P0 | A/B 实验全流程 | 能口述随机化、SRM、样本量、主指标/护栏、置信区间、上线决策，并产出一份报告 |
| P0 | 业务分析表达 | 5 分钟内讲清“异常是什么 → 怎么拆 → 怎么验证 → 建议与风险” |
| P1 | 搜索/内容/直播业务 | 各画一张指标树，能解释曝光、点击、消费、留存之间的关系和口径 |
| P1 | 因果方法边界 | 能解释 PSM、DiD、DML、Uplift 何时用、核心假设和常见误用 |
| P1 | 推荐算法 | 跑通召回/排序基线，说明离线指标与线上目标的差别 |
| P2 | Agent 评估、画像标签 | 明确任务成功率与留存、标签覆盖率/准确性/稳定性如何衡量 |

## 文件使用顺序

1. [14 天学习计划](02-14天学习计划.md)：每天做什么、交什么、怎样验收。
2. [练习项目与验收标准](04-练习项目与验收.md)：用一个可复现的数据项目覆盖多岗位，再做推荐算法加练。
3. [岗位专项与面试题](03-岗位专项与面试题.md)：拿到面试通知后，按公司和岗位做 60–90 分钟定向复盘。

## 面试提前时

若只剩 48 小时：第一天完成 SQL 留存/漏斗/窗口函数和 1 页指标树；第二天完成 A/B 流程、SRM、案例口述，并按目标岗位读专项卡。推荐算法面试则把第二天一半时间改为召回/排序基线、AUC/Recall@K、数据泄漏与冷启动。先保证能清楚解释自己简历中的真实项目。

## 进度记录

每晚在纸上或自己的任务工具里记 3 项：**已完成的证据、没讲清的问题、明天的第一步**。不要只记录学习时长。面试前把所有项目陈述压缩为 1 分钟和 3 分钟两版。
