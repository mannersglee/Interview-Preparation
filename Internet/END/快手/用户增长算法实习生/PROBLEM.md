# 题目目标
使用前端技术栈，实现一个 **Web 版待办事项管理系统（Todo App）**。

# 题目描述
实现一个运行在浏览器端的待办事项管理工具，帮助用户记录和追踪日常任务。用户可以通过该工具添加、查看、编辑和删除任务，区分任务是否已完成，以及在任务较多时快速找到目标。页面刷新后数据不丢失。

## 关键取舍
考虑到答题时间有限，以下内容**不做强制要求**，可根据自身情况取舍：
- 无需过度关注异常处理和边界防御，保证正常流程可用即可。
- UI 做到整洁可辨认即可，不必像素级对齐。
- 无需处理多用户、权限、国际化等内容。

# 总体约束
1. **技术栈自由选择**：纯 HTML/CSS/JS、React、Vue 等均可。
2. **UI 自由发挥**：界面清晰可用、风格简洁现代即可，无设计稿对齐要求。
3. **AI 编程工具不做限制**，但需自行理解题目并确保代码质量。
4. **代码规范**：结构清晰、注释合理、命名规范。

# 必做功能
完成以下核心能力即达到基本要求：

- 任务具备基础属性，能够被创建、展示、编辑和删除。
- 任务可在"进行中"和"已完成"两种状态间切换，且两种状态有明确的视觉区分。
- 支持按任务完成状态筛选列表。
- 支持通过文本匹配搜索任务。
- 数据在浏览器端持久化，刷新不丢失。

# 进阶要求
以下为加分方向，不限定具体实现形式，展示更多工程能力即可：

- 更丰富的任务属性与内容编辑体验。
- 任务的排序、归类或视图切换能力。
- 截止日期相关的视觉提醒。
- 空状态、批量操作、响应式适配、过渡动效等体验优化。
- 引入后端服务，实现数据持久化存储或多端同步。
- 任何你认为能提升产品体验的创意。

# 验收要求
能够顺畅走通"添加任务 → 标记完成 → 筛选查看 → 搜索定位 → 删除确认 → 刷新恢复"的完整闭环，即达到基础要求。面试官将通过实际操作感受交互流畅度和功能完整度。
