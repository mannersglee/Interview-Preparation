# 用户增长算法实习生：岗位理解

## 如何理解工作内容

这份岗位的核心问题是：在金币、任务等激励场景中，把有限的补贴给到**因补贴而增加活跃或改善体验**的用户，并决定补贴金额。优化对象不是领取率本身，而是增量 DAU、留存、用户体验与补贴成本之间的权衡。主站和极速版的人群、行为与补贴敏感度可能不同，需要分别验证，再决定是否共享模型。

一个典型闭环是：定义业务目标和约束 → 设计随机实验并采集曝光、领取、活跃、成本等日志 → 估计不同用户和金额的增量效果 → 在预算与体验约束下分配补贴 → 小流量 A/B 测试 → 监控长期效果、成本与异常。亿级补贴规模意味着算法不仅要有离线指标，还要能稳定上线、控制预算和防止刷量。

## 快速入门术语

| 术语 | 含义 | 在本岗位中的用途 |
| --- | --- | --- |
| DAU / MAU | 日 / 月活跃用户数 | 业务规模指标；应关注增量而非自然活跃 |
| 留存 | 用户在后续日期继续活跃的比例 | 防止短期补贴只带来一次性活跃 |
| ROI | 收益与投入的比值，口径须明确 | 比较增量活跃价值与补贴成本 |
| A/B 测试 | 用户随机分组比较策略效果 | 识别上线策略的因果效果 |
| ATE / CATE | 平均 / 条件平均处理效应 | 估计总体或不同人群的补贴增量效果 |
| Uplift | 干预导致的结果变化 | 区分本来就会活跃和真正被激励的用户 |
| 倾向得分 | 历史策略下接受某补贴的概率 | 纠正非随机日志的选择偏差；需要重叠性 |
| IPS / DR | 逆倾向加权 / 双重稳健估计 | 离线评估新策略，依赖准确日志与假设 |
| 出价 | 对用户或场景确定补贴金额 | 在成本、效果和约束间选择动作 |
| 强化学习 / Bandit | 通过反馈逐步学习决策 | 处理探索与利用、长期价值和变化中的环境 |
| 生成式出价 | 用生成模型产生候选动作或金额分布 | 探索复杂出价空间；仍需约束、校准和在线验证 |
| 护栏指标 | 不能明显恶化的体验或风险指标 | 如投诉、疲劳、刷量、留存和预算超支 |

## 实际工作中的问题与解法

1. **把相关性误认为增量。** 高活跃用户往往也更容易领金币。用随机实验建立可信标签；历史非随机日志需记录倾向概率，并检查重叠性、采用 IPS/DR 等方法。
2. **补贴金额和结果存在非线性。** 金额过小无效，过大则边际收益下降。将多个金额视作离散动作，学习剂量反应曲线；在预算下按增量价值减成本优化。
3. **短期 DAU 与长期体验冲突。** 只优化当天活跃可能诱导疲劳或薅羊毛。加入 7/30 日留存、投诉、任务完成质量等指标，设置用户频控与护栏。
4. **离线好、上线差。** 原因可能是分布漂移、未记录的策略概率、数据泄漏或反馈延迟。采用时间切分、回放评估、灰度实验和持续监控；关键特征需保证训练与服务一致。
5. **预算节奏失控。** 按日总预算和小时节奏约束投放，对异常流量和补贴集中度报警；大规模执行可采用候选集排序、分桶和实时预算控制。
6. **实验被干扰。** 用户跨设备、跨产品或社交传播会破坏独立性。明确随机化单元、去重口径，必要时按用户或地域聚类分析，并监测样本比例异常。

## 架构瓶颈与可行优化

可采用“数据与实验层 → 效果估计层 → 约束决策层 → 在线服务层 → 监控复盘层”的架构。数据层统一用户、任务、补贴、结果及 propensity 日志；估计层输出各金额的增量效果和不确定性；决策层纳入预算、频控、公平性及体验护栏；在线层保证低延迟和降级策略；监控层追踪真实增量、预算、漂移与风险。

现实中的主要瓶颈是随机探索成本高、长期结果反馈慢、动作空间大、策略更新改变数据分布。可先用小规模随机实验打底，逐步引入 DR 评估和保守策略改进；对长期价值使用代理指标但保留长期 A/B 校验；生成式模型只负责生成候选金额，最终由约束优化器筛选，并设置可解释的回退策略。所有改进都需要在线实验确认，模拟或离线结果不能直接当作业务收益。
